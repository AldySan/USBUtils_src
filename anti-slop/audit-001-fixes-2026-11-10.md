# antislop audit 001: fix report (2026-11-10)

Scope: all six findings approved by the owner ("Seluruhnya diperbaiki").
Branch: `fix/antislop-audit-001` (local only; not pushed, not released).

## What was fixed

### Finding 1 (R-02, HIGH): em dashes removed from user-facing text

All em dash characters were replaced with a comma, colon, period, or
parentheses in the strings shown to users: 8 GUI files plus the 3 core
strings that surface in GUI message boxes and CLI output
(`ps2load.cpp`, `gameops.cpp`, `usbdevice.cpp`). Em dashes inside code
comments, `docs/`, and `README.md` were deliberately left alone: R-02
governs interface text, not developer documentation.

### Finding 2 (R-25, HIGH): green chip now meets AA

Chip text `#1a7f37` (4.47:1 on its pastel background) replaced with
`#146c43` (5.68:1 on `#e6f4ea`, 6.45:1 on white). The red pair already
passed and is unchanged.

### Finding 3 (R-25/R-34, HIGH): colors now follow the system theme

- Welcome screen: inline `color:#555` removed; the label now uses the
  palette text color on every theme.
- Muted hint labels (ISO explorer source/info lines, config dialog note):
  `color:#666` replaced with the palette's disabled WindowText color,
  which adapts to light and dark themes.
- Support-files summary label: theme-aware pair, light `#146c43` /
`#f6ad55` dark, amber light `#b45309` / dark `#f6ad55`; chosen by
  `QPalette::Window` lightness. Computed contrast (WCAG relative
  luminance): light green 6.45:1, light amber 5.02:1, dark green
  10.08:1, dark amber 8.75:1 against representative light/dark window
  backgrounds; the dark pair also stays above 4.5:1 on the darker
  `#353535` variant.
- Chips keep their fixed pastel backgrounds, so their contrast is
  self-contained on any theme.

### Finding 4 (C-5, LOW): README cancelability claim corrected

"all long operations run on worker threads with cancelable progress bars"
now reads: long copy jobs (install, export, copy, move, remove) are
cancelable, quick scans (game file lists, video scan, find-file) show a
busy dialog instead. The scans themselves were not given Cancel buttons:
their core engines (`listGameFiles`, `scanVideos`, `findFileInGames`)
have no cancellation point, and adding one is an engine API change, not
a copy fix. Flagged for a future task if wanted.

### Finding 5 (R-37, LOW): design direction recorded

`DESIGN.md` added at the repo root: soul (comfort and ease), style
(modern minimalist, clean, professional), dials ENERGY 1 / RHYTHM 1 /
MOTION 1, and non-goals.

### Finding 6 (C-1, LOW): panel title clarified

Group box "Useful acquired — support files" renamed to "Support files";
the historical name moved into the tooltip ("the original's 'Useful
acquired' panel") and the README feature table. The config dialog
category and two header doc comments were aligned.

## Additional pre-existing defect found and fixed during verification

`supportPanel_` was constructed but never added to the main layout, so
the entire support-files strip never appeared in the window (verified at
HEAD before any of today's edits; not introduced by this change set).
Fixed with `root->addWidget(supportPanel_)` in the MainWindow
constructor. This is also why the audit's screenshots-based checks
initially showed no chip pixels.

## Verification (R-35)

- Build: full CMake build succeeded (core + CLI + tests + GUI) with
  GCC and Qt 6.8.3, `-Wall -Wextra`, no warnings from the changed files.
- Tests: `ctest` 1/1 passed (`usbutils_tests`); `usbutils --version`
  runs.
- Grep checks: no em dash remains in `src/` outside comments; no
  `#555`/`#666`/`#1a7f37` remains; no dead references to the old panel
  title.
- Runtime: the GUI was launched headless (Qt offscreen platform) in
  both a light and a dark palette, with `USBUTILS_DATA` pointing at the
  shipped data files. Both runs exited cleanly (rc=0, no Qt warnings on
  stderr beyond the expected offscreen `propagateSizeHints` notice).
  Screenshots were captured and pixel-verified: summary renders
  `#146c43` in light mode and `#6ee08a` in dark mode; chips render with
  the pastel background and `#146c43` text in both themes.
- Limits, stated honestly: no interactive click-through was performed
  (no display or input automation in this environment). Control wiring,
  dialog behavior, and unchanged features were verified by code
  inspection; no control was added, removed, or rewired by this change
  set except the layout placement above.
