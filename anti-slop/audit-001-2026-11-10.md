## Findings

### 1. HIGH - R-02: em dash character in user-facing text

Reason: R-02 forbids the em dash (`—`) in any UI text; it must be replaced
with a comma, colon, period, or parentheses.

The character appears in roughly 40 distinct user-facing strings (about 55
raw instances) across 8 GUI files and 3 core files whose strings are shown in
both the GUI and CLI:

- `src/gui/mainwindow.cpp`: 80 (window title), 118 and 484 (welcome HTML),
  240 (PS2Load tooltip), 255 (status bar "Ready..."), 411, 526, 575, 698,
  740, 792 (group box title), 833/835 (chip tooltips), 1091, 1128, 1212,
  1221, 1226, 1257, 1273, 1285, 1289, 1521 (About)
- `src/gui/gamefilesdialog.cpp`: 194, 285, 298
- `src/gui/videoripdialog.cpp`: 39 (window title), 183, 305, 318
- `src/gui/ps2loaddialog.cpp`: 57 (window title), 66, 146
- `src/gui/dnasdialog.cpp`: 27 (window title), 50, 125, 161
- `src/gui/isoexplorerdialog.cpp`: 49, 64, 205, 267, 277/278 (window title),
  560, 579
- `src/gui/finddialog.cpp`: 97, 199, 211, 224
- `src/gui/configdialog.cpp`: 37 (window title), 56, 61, 118, 120, 148, 160,
  172 (clipboard export text)
- Core strings surfaced in message boxes and CLI output:
  `src/core/ps2load.cpp:322`, `src/core/gameops.cpp:258`,
  `src/core/usbdevice.cpp:271, 295` (drive display labels)

Out of scope for this finding (kept as is): em dashes inside code comments,
`docs/`, and `README.md`, because R-02 governs interface text, not developer
documentation.

Suggested fix: mechanical replacement per string; in most spots a colon or
comma reads naturally ("Ready: select a USB drive...", "PS2Load: %1",
"Installed \"%1\": parts...").

### 2. HIGH - R-25: green support-file chip fails AA contrast

Reason: R-25 requires 4.5:1 for normal text; the "found" chip renders
`#1a7f37` text on `#e6f4ea` background, which measures 4.47:1 (computed, not
estimated).

Location: `src/gui/mainwindow.cpp:837-842` (`updateSupportPanel`, found-state
chips and the bold summary when all files are present).

Suggested fix: darken the green. `#146c43` measures 5.68:1 on `#e6f4ea` and
6.45:1 on white, stays visually close to the current color. The red pair
(`#b91c1c` on `#fde8e8`, 5.51:1) passes and needs no change.

### 3. HIGH - R-25 / R-34: hardcoded light-theme colors break dark system palettes

Reason: R-25 requires contrast across the entire area text sits on, and R-34
requires every theme that actually renders to work. Qt Widgets follows the OS
palette, so on a dark system theme these fixed foreground colors sit on a
dark window background and fail AA:

- `src/gui/mainwindow.cpp:111,113,477,479`: welcome HTML `color:#555`
  (7.46:1 on white, 2.24:1 on a dark palette)
- `src/gui/isoexplorerdialog.cpp:58,113` and `src/gui/configdialog.cpp:57`:
  `color:#666` muted labels (5.74:1 on white, 2.90:1 on dark)
- `src/gui/mainwindow.cpp:819-821`: amber summary `#b45309` used when some
  support files are missing (5.02:1 on white, 3.32:1 on dark)

Suggested fix: derive these from the palette (for example QPalette
WindowText / disabled text) so the OS theme decides, or pin both foreground
and background in the stylesheet. The pastel chip backgrounds are
self-contained and keep their contrast, but re-check them together with the
palette rework.

### 4. LOW - C-5: README overstates cancelability of long operations

Reason: C-5 (evidence over claims). README line "all long operations run on
worker threads with cancelable progress bars" does not hold for three scans
that show a progress dialog with an empty cancel label (no Cancel button):

- `src/gui/gamefilesdialog.cpp:96-98` (file list of a game)
- `src/gui/videoripdialog.cpp:103-105` (video scan)
- `src/gui/finddialog.cpp:107-108` (find in games)

Install/export/copy/move/remove jobs DO have a working Cancel
(`MainWindow::runJob`). Suggested fix: either add cancellation to the three
scans or soften the README sentence ("long copy operations are cancelable").

### 5. LOW - R-37: design direction exists only in conversation

Reason: R-37 requires the direction to be loaded before UI work; right now
"modern minimalist, comfort and ease" lives only in chat. Record it in the
repo (a short DESIGN.md with the brand soul and the ENERGY 1 / RHYTHM 1 /
MOTION 1 dials) so future UI changes keep the same character.

### 6. LOW (optional) - C-1: "Useful acquired" group title wording

Reason: copy clarity for the non-technical audience the README names. The
title "Useful acquired — support files" is a faithful port of the 2009
original (documented in the README), which is a legitimate reason to keep it,
but it reads as broken English on its own. Optional middle ground: plain
lead first, original name second, e.g. "Support files (the original's
'Useful acquired')". Owner decides; keeping the current title is also a
defensible choice given the fidelity goal.
